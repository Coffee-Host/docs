當 Minecraft 主機可以正常運作，但您所在的網路出現無法連線、頻繁逾時、封包遺失或延遲偏高時，可以使用 Cloudflare WARP 測試另一條網路傳輸路徑。WARP 會將裝置的網路流量經由 Cloudflare 網路傳送，適合用來判斷問題是否出在原本的 ISP 路由。

WARP 不一定會讓所有連線變快；如果原本的路徑已經是最佳路徑，開啟後反而可能增加延遲。因此，請先記錄開啟前的測試結果，再與開啟 WARP 後的結果比較。

<Callout type="info" title="什麼情況適合測試 WARP？">
- Minecraft 主機只有在特定 ISP、Wi-Fi 或行動網路下無法連線。
- 可以連線，但延遲突然升高、頻繁逾時或封包遺失。
- 同一台主機在其他網路可以正常連線，只有目前網路異常。
- 客服請您測試 Cloudflare WARP 這條替代連線路徑。
</Callout>

<Callout type="warn" title="使用前請先知道">
WARP 不是匿名工具，也不能讓您偽裝成其他國家的使用者。它只會改變裝置前往網際網路的傳輸路徑；伺服器離線、連接埠關閉、帳號權限錯誤或遊戲服務本身故障，無法透過 WARP 修復。
</Callout>

## 使用前先記錄原本的連線

請先準備 Minecraft 主機的連線位址與連接埠。若客服已提供完整位址，例如 `play.example.com:25565`，請將主機位址與連接埠分開記下：

- **主機位址：** `play.example.com`
- **連接埠：** `25565`

如果您使用的是 SRV 網域，請直接使用遊戲內實際輸入的連線位址進行測試。

<Steps>
<Step>
### 開啟命令提示字元

1. 按下 **Win + R** 開啟「執行」視窗。
2. 輸入 `cmd`，按下 **Enter**。

**請框選：** 框住輸入欄位與「確定」按鈕，並用箭頭標記「輸入 cmd → 按確定」；不要顯示使用者名稱或其他已輸入的命令。

**圖片下方引導文字：**「按下 Win + R，輸入 cmd，再按『確定』開啟命令提示字元。」
</Callout>

<Step>
### 測試開啟 WARP 前的連線

在命令提示字元中，將 `<主機位址>` 替換成您的主機位址，執行：

```text
ping -n 20 <主機位址>
```

若您知道連接埠，也可以開啟 PowerShell，將 `<連接埠>` 替換成實際數字後執行：

```powershell
Test-NetConnection <主機位址> -Port <連接埠>
```

請記下 `Average`、`Lost`，以及 `TcpTestSucceeded` 顯示的結果。這是開啟 WARP 前的基準，稍後要與 WARP 開啟後比較。

**請框選：** 框住封包遺失率、平均延遲，以及 `TcpTestSucceeded`；請遮蔽 Windows 使用者名稱、內部 IP 或其他不必要的命令內容。

## 開啟 WARP 並連線

<Steps>
<Step>
### 接受初次設定

第一次開啟 WARP 時，請依畫面按 **Next**，閱讀並接受 Cloudflare 的隱私政策，直到進入主畫面。這些畫面只會在第一次啟動時出現。
</Step>

<Step>
### 開啟 WARP 開關

在主畫面中央找到連線開關，按一下將它開啟。請等待數秒，直到畫面顯示 **Connected**、**已連線** 或類似的連線成功狀態。

如果偏好設定中顯示連線模式，請保留預設的 **WARP／完整流量連線**，讓整台電腦的連線都經由 WARP 傳送；不需要額外修改其他進階設定。

## 使用 WARP 後重新測試

請保持 WARP 開啟，回到命令提示字元或 PowerShell，使用與前面完全相同的主機位址、連接埠與指令重新測試：

```text
ping -n 20 <主機位址>
```

```powershell
Test-NetConnection <主機位址> -Port <連接埠>
```

比較開啟前後的平均延遲、封包遺失率與 `TcpTestSucceeded`：

- 平均延遲降低、封包遺失減少，且連接埠測試成功：可以保持 WARP 開啟，再進入 Minecraft 測試。
- 結果差不多：WARP 對目前網路路由沒有明顯改善，可以依使用習慣決定是否保留。
- 延遲變高、封包遺失增加或測試失敗：請關閉 WARP，恢復原本連線後再回報客服。

## 進入 Minecraft 測試

1. 保持 WARP 顯示 **Connected／已連線**。
2. 開啟 Minecraft，進入多人遊戲或伺服器清單。
3. 使用原本的伺服器位址與連接埠，不要因為開啟 WARP 而修改遊戲內設定。
4. 進入伺服器後，實際移動、開啟箱子或進行幾分鐘遊戲，觀察是否仍會斷線或延遲升高。

如果只有開啟 WARP 時可以連線，請回報「原本網路」與「WARP」兩組測試結果，這能幫助客服判斷原本 ISP 的路由問題。

## 關閉 WARP 或恢復原本連線

如果 WARP 沒有改善問題，或開啟後反而變慢，請在工作列通知區域點擊 WARP 圖示，再按一下主畫面中央開關，直到狀態顯示 **Disconnected／已中斷**。關閉 WARP 後，Windows 會恢復使用原本的網路連線。

若關閉後網路沒有恢復：

1. 等待約 10 秒後重新連接 Wi-Fi 或網路線。
2. 關閉其他 VPN、Proxy 或加速器。
3. 重新啟動 WARP，再關閉一次。
4. 仍然無法上網時，重新啟動電腦並確認一般網路是否正常。

**請截圖：** WARP 主畫面顯示 `Disconnected`／`已中斷` 的狀態。

**請框選：** 框住中央開關與已中斷狀態，並標記「按此關閉 WARP」；不要顯示裝置名稱或帳號資訊。

## 常見問題

<Callout type="warn" title="WARP 無法連線">
先確認一般網路可以開啟網站，再暫時關閉其他 VPN、Proxy、加速器及防毒軟體的網路過濾功能。若仍無法連線，請重新啟動 WARP 或電腦；不要同時啟用多個 VPN 工具。
</Callout>

- **開啟 WARP 後所有網站都無法開啟：** 先關閉 WARP，確認原本網路恢復後，再嘗試重新連線。
- **Minecraft 仍然無法連線：** 確認伺服器位址、連接埠及伺服器狀態，並比較 WARP 開啟前後的 `Test-NetConnection` 結果。
- **延遲沒有降低：** WARP 不保證每個 ISP 或每個目的地都會有更短路徑；以實際 `ping`、封包遺失及遊戲體驗為準。
- **WARP 連線一下就中斷：** 檢查 Wi-Fi 是否穩定，並確認公司、學校或公共網路沒有封鎖 WARP 所需的連線。

回報問題時，請提供發生時間、主機位址與連接埠、WARP 開啟前後的測試結果、WARP 顯示的連線狀態，以及 Minecraft 的完整錯誤訊息。截圖前請先遮蔽帳號、玩家名稱、公開 IP 與其他個人資訊。
